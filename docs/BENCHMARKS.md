# Замеры RVCMac

Все записи сняты офлайн-харнессом `rvcmac-harness`, если не указано другое. Субъективная задержка здесь не измеряется и с измеренной не смешивается.

## Baseline v0.3-audit (коммит `1d196d7`, 2026-11-09)

**Условия.** MacBook Air M2, 8 ГБ, macOS 27.0.0 (26A428), зарядка, Low Power Mode выключен, термостатус nominal. На машине работали Chrome и Discord, поэтому между сессиями возможен разброс (см. A/B ниже).

**Вход и параметры.** Синтетический голос 20 с (`--synthetic 20`), 3 прогона, `--pacing realtime`, голос `gaechkatm`, pitch +12, protect 0,33. Index 0,75 (b100) и 0,7533 (b150). 100/500/50 — 44,1 кГц, gate −60. 150/500/100 — 48 кГц, gate −200. Тембр и F0 на синтетике проверять нельзя: для этого нужен `TestAudio/`.

**Как читать.** Время этапов — монотонное время вокруг вызовов, прогретые блоки. RAM — `phys_footprint` и RSS на каждый блок (`blocks.csv`). Рост памяти — наклон МНК. Задержка и underrun из `queueModel` **расчётные**: модель очереди не откалибрована и, вероятно, завышает underrun. Реальную полную задержку даёт только live-сессия, на этом коде она не снималась.

### Разброс между сессиями

Один и тот же код ANE+GPU 100/500/50, 4 прогона по 20 с вперемежку: p50 блока 62–76 мс, тогда как в таблице выше 55,2 мс. Поэтому различия во времени меньше примерно 20% между отдельными сессиями считать значимыми нельзя; сравнивать надо чередующимся A/B.

## Загрузка моделей (2026-11-09, коммит `1d196d7`)

ANE+GPU, `gaechkatm`, 100/500/50, два запуска подряд.

| Запуск | Загрузка, мс |
|---|---|
| Харнесс, новая идентичность процесса: 1-й | 38433 |
| Харнесс, новая идентичность процесса: 2-й | 930 |
| Бандл с идентичностью приложения: 1-й | 35499 |
| Бандл с идентичностью приложения: 2-й | 832 |
| Харнесс, обычный: два запуска подряд | 938, 208 |
| Харнесс, `--home` на реальный путь моделей, а не через симлинк | 304, 191 |

**Вывод.** Кэш работает, модели заново не компилируются. Даты `.mlmodelc` остаются от 29 октября. Первая загрузка 35–74 с — это сборка кэша ANE/e5rt, который ведётся отдельно на каждый процесс или бандл (`~/Library/Caches/<имя или bundle id>/com.apple.e5rt.e5bundlecache`, подкаталог по сборке ОС). `homeOverride` и смена пути на кэш не влияют.

Сценарий «приложение» проверен запуском харнесса внутри бандла с bundle id приложения: это эмуляция, а не сам `RVCMac.app`. Настоящее приложение: `app.log` содержит 39,3 с при первой загрузке и 0,9 с при тёплой.

## Утечка памяти: `autoreleasepool` (2026-11-09)

Изменение: `autoreleasepool` вокруг обработки блока в `VoicePipeline.process` (коммит `cb4913e`). Поток inference не возвращается в run loop, поэтому autoreleased-объекты копились до конца сессии. Какие именно объекты держали память, не устанавливалось: пул устранил рост целиком. Условия те же, что у baseline.

| Конфигурация | Наклон footprint до → после, МБ/блок | Пик footprint до → после, МБ |
|---|---|---|
| ANE+GPU 100/500/50 | 1,066 → −0,007 | 760 → 160 |
| ANE+GPU 150/500/100 | 1,312 → −0,000 | 652 → 163 |
| CPU 100/500/50 | 0,227 → −0,013 | 199 → 105 |
| CPU+GPU 100/500/50 | 1,073 → −0,012 | 798 → 184 |

Выход побитово совпадает с baseline во всех 4 режимах.

**Время: чередующийся A/B** (коммит `f6eceac`, харнесс измеряет настенное время всего вызова `process`, включая снятие пула). 3 раунда по 20 с, realtime, 100/500/50. Варианты: без пула, с пулом, с пулом и `outputBackings` (предвыделенные обычные `MLMultiArray` для трёх выходов; в код не вошло).

| ANE+GPU | пул | 62,6 / 69,8 / 69,2 | 76,6 / 81,1 / 80,5 | ≈0 | 159 |

Цены у пула не видно: настенное время в пределах разброса. `outputBackings` на этих данных выигрыша по памяти и времени не дал, поэтому в код не включён. Вариант с `MLMultiArray` на `CVPixelBuffer`/IOSurface не проверялся.

Наклон footprint проверен только на харнессе, живая сессия приложения после исправления не снималась.
