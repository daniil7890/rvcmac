## Baseline v0.3-audit (коммит `1d196d7`, 2026-11-09)

**Условия.** MacBook Air M2, 8 ГБ, macOS 27.0.0 (26A428), зарядка, Low Power Mode выключен, термостатус nominal. На машине работали Chrome и Discord, поэтому между сессиями возможен разброс (см. A/B ниже).

**Вход и параметры.** Синтетический голос 20 с (`--synthetic 20`), 3 прогона, `--pacing realtime`, голос `gaechkatm`, pitch +12, protect 0,33. Index 0,75 (b100) и 0,7533 (b150). 100/500/50 — 44,1 кГц, gate −60. 150/500/100 — 48 кГц, gate −200. Тембр и F0 на синтетике проверять нельзя: для этого нужен `TestAudio/`.

Задержка и underrun из `queueModel` **расчётные**: модель очереди не откалибрована и, вероятно, завышает underrun. Реальную полную задержку даёт только live-сессия, на этом коде она не снималась.

## Пороги качества (предварительные)

**Статус: предварительные.** Подобраны на одном голосе (`gaechkatm`) и синтетике (`TestAudio` из ElevenLabs). Пересмотреть после добавления живых записей с микрофона или второго голоса. Проверены только на данных, на которых подобраны.

Метрики считает `scripts/quality_gate.py`. Сравнение: кандидат минус эталон **той же конфигурации и того же режима**, на сидах 1 и 2 (сид по умолчанию равен 1). Эталон: `reports/quality-baseline-e725643/` (конфигурация 100/500/50). Для сравнения разных режимов (CPU и ANE+GPU) эти пороги не подходят.

| Метрика | Что сравниваем | На файл | Среднее по 10 файлам |
|---|---|---|---|
| Щелчки на границах блоков | абсолют, кандидат | 0 | сумма ≤ 1 |
| Скачки на границах блоков (`bound_jumps`) | абсолют, кандидат | 0 | сумма ≤ 1 |
| Щелчки всего | разность | ≤ +9 | ≤ +2,5 |

| Доля F0 >50 центов, по модулю октавы | разность | ≤ +0,05 | ≤ +0,015 |
| Дрожание F0 | разность | ≤ +9 центов | ≤ +3 цента |
| Усиление/RMS активной части, модуль | разность | ≤ 0,35 дБ | ≤ 0,12 дБ |

**Правило одиночного срабатывания.** Если порог превышен один раз, повторить прогон на другом сиде и засчитывать нарушение, только если оно повторилось. Ориентировочная доля ложных тревог на полный прогон всех метрик — 5–15%.

Порог щелчков на границах отдельный, потому что дефект gate из 24 граничных щелчков дал лишь +2,4 к общему счёту в среднем. Доля октавных кадров F0 — диагностика без порога. Абсолютные значения щелчков и F0 не означают число слышимых дефектов: детектор срабатывает и на чистой речи, pyin даёт октавные ошибки.

## Исправление тайм-аута stop, C2 (2026-11-13)

`VoiceEngine.stop()` больше не возвращает управление с живым worker: токен сессии и приватный семафор завершения на каждую сессию (`WorkerSession`), тайм-аут 3 с только сообщает о медленном выходе, join продолжается до сигнала. Запоздалый сигнал старой сессии не может удовлетворить новый stop.

Харнесс не использует `VoiceEngine` (гоняет `VoicePipeline` напрямую), поэтому C2 вне его пути обработки. Проверка: 7 новых юнит-тестов `WorkerSessionTests` (токены, join, медленный выход, запоздалый сигнал), `swift test` — 45 тестов, 0 падений; `swift build -c release --arch arm64` проходит; ревью `rt-audio-reviewer` — замечаний к RT-пути нет. Контрольный прогон харнесса до и после правки: `01_normal`, CPU, 100/500/50, 48 кГц, gate −60, сид 1, pacing fast — выходы побайтово совпали между собой и с эталоном `reports/quality-baseline-e725643/seed-1/cpu/01_normal`. Путь обработки не менялся; живая сессия не проверялась.

## Экспорт отчёта без блокировки воркера, B4 (2026-11-13)

Запись телеметрии на воркере (`recorder.append`, `setLatency`, чтение `total`) переведена на `withLockIfAvailable`: при занятом локе строка пропускается и считается в `Report.Counters.droppedRows`. Экспорт берёт под локом только плоский снапшот хранилища (`BlockRecorder.snapshot`, одна копия без построчных аллокаций), материализация строк и JSON/CSV — вне лока. `AppState.stop()` строит отчёт после `engine.stop()`: воркер уже завершён, отчёт видит все блоки; частоты и задержки устройств сохраняются после `io.stop()` (проверено по коду `AudioIO`). Старые отчёты декодируются: отсутствующие ключи counters получают дефолты.

Харнесс не использует `VoiceEngine` (гоняет `VoicePipeline` напрямую), поэтому B4 вне его пути обработки. Проверка: 7 новых юнит-тестов `BlockRecorderTests` (снапшот, независимость снапшота до и после wrap, try-lock, декодирование старых отчётов), `swift test` — 52 теста, 0 падений; `swift build -c release --arch arm64` проходит. Контрольный прогон харнесса до и после: `01_normal`, CPU, 100/500/50, 48 кГц, gate −60, сид 1, pacing fast — выход побайтово совпал с прогоном до правки и с эталоном `reports/quality-baseline-e725643/seed-1/cpu/01_normal`. Путь обработки не менялся; живая сессия не проверялась.

Уточнения B4 (2026-11-13): пропуск append не попадает в pending — добавлен тест `testSkippedAppendDoesNotCorruptLatencyOfAnyRow` (wrap + занятый лок, latency каждой строки не портится); частоты/задержки устройств снимаются в локальные до `engine.stop()` и передаются в отчёт явно — зависимость от сохранности полей в `io.stop()` убрана; `recorder.total` при неудаче try-lock отдаёт последнее известное значение (проверено, поведение сохранено); `setLatency` в `resolvePending` применяется одним try-lock к предаллоцированному батчу вместо лока на каждую строку (до 64). `swift test` — 55 тестов, 0 падений; `swift build -c release --arch arm64` проходит; харнесс A/B (`01_normal`, CPU, 100/500/50, 48 кГц, gate −60, сид 1, pacing fast) — выход побайтово совпал с эталоном `reports/quality-baseline-e725643/seed-1/cpu/01_normal`. ## Освобождение моделей в фоне, B5 (2026-11-13)

Старая модель при переключении голоса больше не освобождается на воркере и под `modelLock`: воркер снимает старый `ModelState` и `LoadedVoice` и передаёт их в `ModelReleaser` (serial-очередь, QoS utility). Pipeline в конце сессии передаётся туда же до `done.signal()` — освобождение не зависит от момента, когда Thread-замыкание отпустит захваты (после сигнала). В фон также уходят: перезаписанный pending-голос в `switchModel`, pending в `swapLock` и модели при deinit движка, не подошедший `prepared` при `start()`, перезапись и ошибка прогрева в `prepare()`. Быстрый стоп→старт может кратко держать два набора моделей (освобождение асинхронно), но воркер и main не платят за deinit Core ML.

Харнесс не использует `VoiceEngine` (гоняет `VoicePipeline` напрямую), поэтому B5 вне его пути обработки.
